> Canvas themes export a `typo` dictionary for consistent sizing across components:

| Key | Value | Usage |
|-----|-------|-------|
| `typo.display` | [size]pt | Hero/cover titles, giant numbers |
| `typo.h1` | [size]pt | Slide titles |
| `typo.h2` | [size]pt | Card/section headings |
| `typo.body` | [size]pt | Body text |
| `typo.small` | [size]pt | Captions, footnotes |
| `typo.kicker-size` | [size]pt | Tracked uppercase labels |
| `typo.kicker-tracking` | [value]pt | Letter-spacing for kickers |

### Weight Hierarchy (Canvas themes — choose one)

**Traditional** (consulting, corporate):
- Large titles: Bold (700)
- Body: Regular (400)

**Inverse** (Swiss, editorial):
| Size Range | Weight | Usage |
|---|---|---|
| >= 36pt | 200 (ExtraLight) | Display, hero |
| 24-35pt | 200-300 | Slide titles |
| 16-23pt | 300-400 | Card titles |
| 12-15pt | 400-500 | Body |
| 8-11pt | 500-600 | Kickers, metadata |

### Layout Contract

Record the layout behavior that each reusable component and representative demo
slide must preserve. This makes spacing and equal-height behavior deliberate
rather than accidental.

| Component / slide group | Content relationship | Primitive | Spacing & alignment | Equalization behavior | Demo evidence |
|-------------------------|----------------------|-----------|---------------------|-----------------------|---------------|
| [e.g., metric row] | [comparable peer metrics] | [`cols`] | [centered vertical stack, `.9em`] | [`lazy-layout: true`; exactly one direct card with terminal `lazy-v(1fr)` per column] | [`demo.typ` slide name] |
| [e.g., feature matrix] | [items aligned across rows] | [`grid`] | [row/column gutters and cell alignment] | [fixed rows; no lazy columns] | [`demo.typ` slide name] |

Rules for completing the contract:

- For ordinary prose/content groups, start stack spacing near `.8em` and tune it
  against the rendered typography. Headers and KPI internals use `.8em` or more.
  Smaller positive gaps are
  valid for tiny labels, dimension marks, badges, and coupled primitives; record
  that semantic role instead of applying a global minimum. Use `0pt` only for an
  intentional seamless join and document why the join must be gapless.
  Horizontal stacks are evaluated separately.
- A stat/KPI/metric card that arranges icon → value → label uses one centered
  `stack(spacing: .8em)` or larger and no internal `v()` spacer. Tune the spacing
  against the rendered typography. At caller level, keep complete components in
  natural flow by default; do not add a fixed `v()` or wrapper `stack()` merely
  to separate adjacent components. Introduce explicit layout only when the
  rendered design demonstrates a real geometric need.
- Use `cols` for an ordinary one-row column relationship and `grid` for matrices
  or multi-row alignment. Enable `cols(lazy-layout: true)` only for height
  equalization when every column contains exactly one direct stretchable
  component. Keep that component's terminal `lazy-v(1fr)` in its reusable
  definition because the marker is inert when lazy layout is off. Never rely on
  multiple marker-bearing components inside one lazy column.
- Do not introduce a generic wrapper such as `column-layout` that merely forwards
  arguments to `cols` or `grid`. A helper is justified only when it adds stable,
  theme-specific semantics beyond renaming the primitive.
- The demo must cover every declared component and each distinct layout contract,
  including any equal-height behavior, so the compiled PNGs prove the contract.
